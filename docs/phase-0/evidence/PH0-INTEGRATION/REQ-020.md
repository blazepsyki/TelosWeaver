# REQ-020: Rust 1.99.1의 deprecated `fetch_update`로 엄격 Clippy 실패

| 항목 | 값 |
|---|---|
| 요청 | PH0-INTEGRATION (`claude-opus-5.5/session-c9336d2c`) |
| 처리 | **PH0-HOST (Codex)** — 사용자 지정(2026-10-25) |
| 접수 | 2026-10-25, 기준 `main` `11c2262` |
| 우선순위 | G3 Linux 검증 전. Linux Host(`Psyki-NAS`)의 공통 검사가 같은 이유로 막힙니다 |

## 1. 배경

사용자가 Windows와 Linux Host(`Psyki-NAS`)의 Rust를 모두 1.99.1로 올렸습니다(rustup 1.29.2, clippy 0.1.99, rustfmt 1.10.0). 이후 Windows에서 다시 검사한 결과는 아래와 같습니다.

| 명령 | 결과 |
|---|---|
| `cargo test --workspace --locked` | 155개 통과, 32개 실환경 제외 |
| `cargo fmt --all -- --check` | 통과 |
| `cargo clippy --workspace --all-targets --locked -- -D warnings` | **실패 1건** |
| `rn-fork/`: `cargo fmt --check`, `cargo clippy --locked --all-targets -- -D warnings`, 격리 `cargo test --locked` | 모두 통과(204개) |

## 2. 실패 내용

```text
error: use of deprecated method `std::sync::atomic::Atomic::<usize>::fetch_update`: renamed to `try_update` for consistency
error: could not compile `telos-core` (lib) due to 1 previous error
```

위치: `crates/core/src/execution/supervisor.rs:327` (`.fetch_update(Ordering::AcqRel, Ordering::Acquire, |total| { … })`). 저장소에서 `fetch_update`를 쓰는 곳은 여기 하나입니다.

## 3. 요청

1. `fetch_update`를 `try_update`로 바꿉니다. 1.99의 `try_update`는 인자 순서(set 순서, fetch 순서, 클로저)와 반환(`Result<T, T>`)이 같아 동작은 바뀌지 않아야 합니다. 바꾸기 전에 사용 중인 Toolchain의 표준 라이브러리 문서로 시그니처를 확인해 주세요.
2. Workspace 검사(`cargo test --workspace --locked`, 엄격 Clippy, fmt)를 Rust 1.99.1에서 통과시킵니다.
3. 최신 `main`에서 새 Branch·Worktree(예: `ph0/host-req020`)를 만들고 결과를 HOST 증거에 기록한 뒤 INTEGRATION에 통합을 요청합니다. 배정표의 HOST 행·REQ-020 행 갱신 규칙은 기존과 같습니다.

`cargo +1.94.0` 등 이전 Toolchain으로 되돌려 우회하지 않습니다(사용자 결정: 양쪽 Toolchain을 1.99.1로 맞춤).

## 4. 참고

- 이 변경은 Spec·공통 계약을 바꾸지 않습니다.
- 통합 후 INTEGRATION이 Windows와 `Psyki-NAS`에서 공통 검사를 다시 실행합니다([Linux·Remote SSH Host 절차](../../LINUX_REMOTE_HOST.md) §4.2).
