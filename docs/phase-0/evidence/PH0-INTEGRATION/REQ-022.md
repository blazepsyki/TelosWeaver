# REQ-022: `codex exec --thread-source cli` 세션이 VS Code Codex 목록에 표시되지 않음

| 항목 | 값 |
|---|---|
| 요청 | PH0-INTEGRATION (`claude-opus-5.5/session-c9336d2c`) |
| 처리 | **PH0-CODEX (Codex)**: 사용자 지정(2026-10-26) |
| 접수 | 2026-10-26, 기준 `master` `3fdba06` 이후(DEC-08 통합 `f4dc2a7` 포함) |
| 대상 문서 | [`docs/AGENT_CLI_VSCODE_SESSIONS.md`](../../../AGENT_CLI_VSCODE_SESSIONS.md) A절(Codex CLI)과 이를 인용하는 D·F절 |
| 우선순위 | 다음 CLI 위임 전. 외부 에이전트 호출 절차의 Codex 부분이 실제로 동작하지 않음 |

## 1. 배경

사용자는 INTEGRATION이 Codex CLI를 직접 실행해 맡긴 작업(G3 Linux 배정, [통합 증거](README.md) §9.3)을 VS Code Codex 확장에서 보고 싶어 합니다. 문서 A3·D·F절은 `codex exec --thread-source cli`로 실행하면 확장 기본 목록에 들어간다고 안내합니다. A1은 실제 화면 표시는 확인하지 않았다고 적었고, INTEGRATION이 이 부분을 시험했습니다.

## 2. 시험 결과 (Windows 로컬, 2026-10-25~26)

CLI: 확장 동봉 `codex.exe` `0.164.0-alpha.11.1`(`openai.chatgpt-26.1021.22027-win32-x64`). `CODEX_HOME`은 기본값 `C:\Users\Psyki-HOME\.codex`이며 확장의 App Server `initialize` 응답과 같습니다.

| # | 명령 | 세션 ID | Rollout `session_meta` | App Server `thread/list` | VS Code 목록(사용자 확인) |
|---|---|---|---|---|---|
| 1 | `codex exec --skip-git-repo-check -C d:\Downloads\Vibe_dev -s read-only "<프롬프트>"` | `01a1733d-cce2-7d80-8471-6f32757d4bc6` | `source: "exec"`, `originator: "codex_exec"`, `cwd: d:\Downloads\Vibe_dev` | — | **표시 안 됨** |
| 2 | `codex exec --thread-source cli --cd D:\Downloads\Vibe_dev\TelosWeaver -s read-only --json -` | `01a173c5-103f-7e13-8b51-33bd5df6ae80` | `source: "exec"`, **`thread_source: "cli"`**, `cwd: D:\Downloads\Vibe_dev\TelosWeaver` | `source: "exec"` (`sourceKinds: ["exec","cli","vscode"]`로 조회) | **표시 안 됨**(Developer: Reload Window 후에도) |

시험 1은 `cwd`가 VS Code에서 연 폴더와 같아도 `exec`는 보이지 않음을, 시험 2는 `--thread-source cli`가 rollout의 `thread_source`만 바꾸고 **목록 필터가 보는 `source`는 `exec`로 남김**을 보여 줍니다. A1이 인용한 기본 필터(`sourceKinds` 생략 시 `cli`·`vscode`)와 맞춰 보면 `exec`로 만든 세션은 이 옵션으로 기본 목록에 들어가지 않습니다.

참고: REQ-021에서 Codex가 확인한 것처럼 **App Server로 만든 Thread**는 `threadSource` 값과 관계없이 `vscode`로 저장돼 기본 목록에 들어갑니다(DEC-08, Spec v1.5.4 §7.6). 차이는 실행 경로(`exec` 대 `app-server`)에 있습니다.

두 시험 Thread는 App Server `thread/archive`로 정리했습니다(응답 `{}`, 2026-10-26).

## 3. 요청

1. 문서 A절의 판단과 절차를 위 결과에 맞게 고칩니다. `--thread-source cli`를 표시 수단으로 안내하지 않고, `thread_source`와 `source`의 차이를 적습니다. 직접 확인할 경우 사용자에게 화면 확인을 요청하고 시험 Thread는 Archive합니다.
2. 외부 에이전트가 Codex 작업을 **확장 목록에 보이게** 맡길 수 있는 실제 방법을 찾아 확인합니다. 후보:
   - `codex app-server`를 직접 띄워 `thread/start`·`turn/start`로 실행(DEC-08 Adapter와 같은 경로). 위임자가 쓸 수 있는 최소 절차(초기화, Thread 시작, 프롬프트 전송, 완료 대기, 종료 코드·이벤트 수집)와 Sandbox·승인 설정 방법
   - `exec fork <ID> --thread-source cli`(A5)가 실제로 `source`를 바꾸는지. 바꾸지 않으면 A5도 고칩니다
   - 다른 `exec` 옵션이나 설정이 있는지(설치 CLI 도움말·확장 코드 기준)
3. 결론을 A1 표(확인한 사실·미확인 동작)와 A3~A6, D절 표, F절 지시 예시에 반영합니다. 실제 화면에서 확인하지 않은 방법은 미검증으로 적습니다.
4. 이 문서는 Spec·공통 계약을 바꾸지 않습니다. Adapter 구현(DEC-08)도 바꾸지 않습니다.

## 4. 작업 방식

- 최신 `master`에서 새 Branch·Worktree(예: `ph0/codex-req022`, `D:\worktree\TelosWeaver\ph0-codex-req022`)를 만들고, 결과를 `docs/AGENT_CLI_VSCODE_SESSIONS.md`와 `evidence/PH0-CODEX/REQ-022.md`에 기록한 뒤 INTEGRATION에 통합을 요청합니다.
- 실계정 시험은 가벼운 모델·일회용 임시 폴더로 하고, 만든 Thread ID를 기록해 병합 시 Archive합니다. 기존 대화는 재개·수정하지 않습니다. 세션 JSONL·SQLite를 직접 고치는 방법은 쓰지 않습니다.
- 배정표의 PH0-CODEX 행·REQ-022 행 갱신 규칙은 기존과 같습니다(단독 커밋, §7 표 행 사이 빈 줄 금지).
