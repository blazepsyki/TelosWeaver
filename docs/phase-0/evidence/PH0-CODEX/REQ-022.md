## 1. 결론

`codex exec --thread-source cli`와 `exec fork … --thread-source cli`는 `thread_source`만 지정하며 실제 목록 분류 `source`는 `exec`입니다. 완료된 Turn이 있어도 기본 DB 목록에는 들어가지 않습니다.

표시할 새 작업은 App Server의 `thread/start`·`turn/start`로 실행합니다. 기존 `exec` 대화는 App Server의 `thread/fork`로 새 `vscode` Thread를 만드는 방법이 기본 DB 목록 포함까지 통과했습니다. 원본 출처는 바뀌지 않습니다. `sourceKinds`는 조회 필터이며 분류 변경 수단이 아닙니다.

이 결과는 DEC-08 Adapter 구현과 같은 실행 경로를 외부 호출 절차에 적용한 것이며 Adapter·Spec·공통 계약은 수정하지 않았습니다. 새 제품 결정 없이 요청 범위에서 처리했습니다.

- `codex --version`, `exec fork --help`, `app-server --help`, `debug app-server send-message-v2 --help`, `unarchive --help`를 확인했습니다.

- DEC-08에서 생성한 로컬 Schema와 이번 설치 CLI의 명령을 사용했습니다. 문서만으로 `--thread-source`의 효과를 추정하지 않았습니다.

## 4. 참고 클라이언트 범위

[req022_app_server.py](req022_app_server.py)는 Python 표준 라이브러리로 작성한 단일 Turn 문서 예제입니다. 초기화·요청 ID 상관·먼저 도착한 알림 보존·명시 권한·실제 정책 검사·완료 대기·프로세스 종료를 다룹니다. stdin·stdout은 UTF-8이며 stdout JSONL과 Native stderr를 분리합니다.

기본은 읽기 전용·승인 never입니다. Workspace 쓰기는 호출자가 명시적으로 선택하며, 응답 정책이 요청과 다르면 Turn 전에 거부합니다. MCP 서버를 비활성화하고 서버가 요구하는 클라이언트 도구·승인을 자동 허용하지 않습니다. 사용자 전역 설정·세션 DB는 직접 수정하지 않습니다.

기본 실행은 목록 확인을 위해 대화를 남기고 `--archive`는 시험 정리용 선택입니다. 기존 원본의 자동 복원·동시 쓰기·Archive는 하지 않습니다. Core의 전체 프로세스 감독·복구·영속 기록을 대체하는 제품 코드가 아닙니다.
