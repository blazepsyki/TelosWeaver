## 1. 실패 재현과 표준 라이브러리 확인

준비 단계에서 main `6ecb5cf`의 `cargo clippy --workspace --all-targets --locked -- -D warnings`를 실행해 `execution/supervisor.rs:327`의 deprecated `fetch_update` 실패를 재현했습니다. 원본 제품 코드에서 사용처는 이 한 곳입니다.

현재 활성 Toolchain의 로컬 문서와 `rust-src`를 확인했습니다. Rust 1.99.1에서 `AtomicUsize`는 `Atomic<usize>`의 별칭입니다. 문서는 `<sysroot>/share/doc/rust/html/std/sync/atomic/type.AtomicUsize.html` 및 `struct.Atomic.html`, 소스는 `<sysroot>/lib/rustlib/src/rust/library/core/src/sync/atomic.rs`입니다.

- 정수형 구현의 `fetch_update`는 Rust 1.99.0부터 deprecated이며 내부에서 `self.try_update(set_order, fetch_order, f)`를 그대로 호출합니다(로컬 소스 3413행).
- `try_update`의 인자 순서는 `set_order`, `fetch_order`, 갱신 함수이며, `usize`의 반환 타입은 `Result<usize, usize>`입니다(로컬 소스 3474행).
- 두 경로의 갱신 함수는 `FnMut(usize) -> Option<usize>`이며, 기존 호출을 새 이름으로 바꾸는 동작 근거를 확인했습니다.

## 2. 변경 범위

제품 코드 변경은 `crates/core/src/execution/supervisor.rs:327`의 메서드 이름 한 곳입니다.

```rust
.try_update(Ordering::AcqRel, Ordering::Acquire, |total| {
```

기존 `AcqRel`·`Acquire`, `checked_add`, 총 이벤트 32 MiB 상한과 `.is_err()` 판정은 유지했습니다. Spec·공통 계약·의존성·Lockfile 변경은 없습니다. 단순 이름 교체이므로 전용 시험을 추가하지 않고 기존 Workspace 시험과 엄격 Clippy로 검증했습니다.
